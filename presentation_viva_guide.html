🧠 Part 2: How It Works in 3 Simple Steps

1. The Eyes (Vision): The smartphone camera captures video frames. The on-device BlazePose neural network predicts 33 3D coordinate keypoints $(X, Y, Z)$ across the body in sub-30ms without sending any video to the internet.
2. The Brain (Math & Kinematics): The app calculates the exact interior angle between joints using atan2 trigonometry (e.g. Hip → Knee → Ankle angle during squats). An Exponential Moving Average (EMA) filter ($\alpha = 0.18$) removes camera shake so optical jitter never causes false rep counts.
3. The Coach (State Machine & Feedback): A multi-phase state machine tracks movement (e.g., Standing → Descending → Bottom Hold → Ascending). When full depth is reached with good spinal alignment, a repetition increments, and a Live Form Score (e.g., 94%) is displayed.

🎓 Part 5: Top 8 Tough Viva Questions & Winning Answers

Q1: Why did you run the AI on the smartphone rather than a powerful cloud server?
Answer: Cloud streaming 30 FPS video introduces 150–300ms latency, which breaks real-time coaching cues. On-device inference delivers sub-30ms response times, works 100% offline, and ensures complete user privacy because raw camera frames never leave the phone.
Q2: What datasets were used to train the pose model?
Answer: The BlazePose model was trained on the COCO Keypoints Dataset (over 200k diverse real-world images for 2D keypoints) and the Google GHUM 3D Dataset (a generative 3D human shape dataset providing 3D depth and occlusion handling).
Q3: How does the system prevent camera shake from counting false reps?
Answer: We apply an Exponential Moving Average (EMA) filter ($\alpha = 0.18$) on calculated joint angles to filter optical jitter, combined with a 4-phase finite state machine that requires full range of motion before incrementing a rep.
Q4: How do you calculate joint angles in 3D?
Answer: Using the 2-argument arctangent formula atan2(Δy, Δx) between three consecutive anatomical landmarks (such as Hip, Knee, and Ankle), normalized between 0° and 180°.
Q5: What happens if there is no internet connection during a workout?
Answer: The app utilizes an offline-first architecture. It saves user sessions into Android SharedPreferences locally and synchronizes with the SQLite backend once network connectivity is re-established.
Q6: How do you adapt to different people's heights and limb lengths?
Answer: We implement an auto-calibration baseline phase that captures $N=30$ standing frames at the start of each session to dynamically adjust depth thresholds to individual body proportions.
Q7: How is user password security handled?
Answer: Passwords are never stored in plaintext. They are salted with a 16-byte cryptographic random salt and hashed using PBKDF2-HMAC-SHA256 with 100,000 iterations.
Q8: Can this app be deployed on other platforms?
Answer: Yes, we built a standalone 64-bit release APK (app-release.apk) that installs on any modern Android device, and also developed a pure Python (OpenCV + MediaPipe) desktop research edition.
